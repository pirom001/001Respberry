# Raspberry Monitor

เว็บมอนิเตอร์ไฟล์ CSV สำหรับ PHP 8+ และ IIS/Apache ใช้ PHP, HTML, CSS และ vanilla JavaScript ส่วนกราฟใช้ Chart.js ผ่าน CDN

## ติดตั้ง

1. วางโปรเจกต์ไว้ที่ `C:\inetpub\wwwroot\001Rasberry` และเปิดเว็บผ่าน IIS หรือ Apache ที่ตั้งค่า PHP 8 ขึ้นไปแล้ว
2. ตั้งค่าแต่ละแหล่ง CSV ใน `config/config.json` หรือหน้า **ตั้งค่าระบบ** โดยกำหนดชื่อ, `dataDirectory`, `filePattern` และ `exportDirectory` ที่บัญชี PHP มีสิทธิ์เขียน
3. ค่าเริ่มต้นมี 3 แหล่ง: `E:\Rasberrypi\GroupSMTFAC3\No04`, `E:\Rasberrypi\GroupSMTFAC3\No05` และ `E:\Rasberrypi\GroupCOATINGFAC3\No01` รูปแบบชื่อไฟล์เริ่มต้นคือ `GSMTFAC3_No04_{date}.csv`, `GSMTFAC3_No05_{date}.csv` และ `GCOATINGFAC3_No01_{date}.csv` ตามลำดับ ตรวจสอบ pattern จริงของแต่ละโฟลเดอร์ก่อนใช้งาน
4. ให้ IIS Application Pool identity (หรือบัญชีที่รัน PHP) มีสิทธิ์อ่านโฟลเดอร์ CSV และมีสิทธิ์เขียนโฟลเดอร์ `config`, `logs` และ `exports`
5. เปิด `index.php` ผ่านเว็บเซิร์ฟเวอร์ แล้วใช้เมนู **ตั้งค่าระบบ** เพื่อเพิ่ม/ลบแหล่งข้อมูล แก้โฟลเดอร์และรูปแบบชื่อไฟล์ พร้อมกำหนดช่วงรีเฟรช

ไม่ควรเปิดเว็บแอปผ่าน `file://` เพราะ PHP API ต้องทำงานผ่านเว็บเซิร์ฟเวอร์ ทั้ง Chart.js, chartjs-plugin-zoom, Hammer.js และฟอนต์เว็บโหลดจาก CDN ซึ่งต้องเชื่อมต่ออินเทอร์เน็ต

## รูปแบบ CSV และการแสดงผล

- รองรับ delimiter แบบ comma, semicolon หรือ tab; แถวแรกต้องเป็น header ที่มีชื่อคอลัมน์และมีอย่างน้อย 2 คอลัมน์
- ตรวจจับคอลัมน์เวลา `timestamp`/`datetime` หรือประกอบ `date` กับ `time`; หากไม่พบจะใช้คอลัมน์แรกเป็นเวลา
- ข้ามแถวหัวตารางที่ซ้ำอยู่ระหว่างข้อมูล เช่นไฟล์ตัวอย่างที่มี `date,time,now,before` ซ้ำ
- เลือกคอลัมน์ตัวเลขเพื่อดูค่าสูงสุด ต่ำสุด และค่าเฉลี่ย; คอลัมน์ข้อความ เช่น `now`/`before` จะแสดงเป็นกราฟหมวดหมู่พร้อม tooltip โดยไม่คำนวณสถิติตัวเลข
- Dashboard อ่านไฟล์ประจำวันที่ตรงกับ `{date}` ในช่วง 30 วันย้อนหลังของแต่ละแหล่ง และอัปเดตตามช่วงรีเฟรช (ค่าเริ่มต้น 8 วินาที); ไฟล์ต้นฉบับจะไม่ถูกลบหรือคัดลอก ระบบจึงต้องเก็บไฟล์รายวันไว้ในโฟลเดอร์ต้นทาง
- เพิ่ม/ลบกราฟจาก Dashboard ได้แยกจากการเพิ่ม/ลบแหล่ง CSV ใน Settings; การซ่อนกราฟไม่ลบแหล่งข้อมูล
- API แสดงข้อมูลกราฟล่าสุดไม่เกิน 2,000 แถวและตารางล่าสุดไม่เกิน 300 แถวต่อแหล่ง แต่จำนวนข้อมูลและสถิติคิดจากทั้ง 30 วัน
- จำกัด CSV รวมย้อนหลังไว้ที่ 50 MB และ 250,000 แถวต่อแหล่งเพื่อควบคุมการใช้หน่วยความจำ

## ตัวอย่างใช้งาน

เมื่อ CSV มี header `date,time,now,before` และข้อมูล `2025/05/02,15:58:55,alarm,start` ให้เลือก `now` หรือ `before` ในกราฟของแหล่งข้อมูลนั้นเพื่อดูสถานะตามเวลา; เมื่อไฟล์มีคอลัมน์ตัวเลข สามารถเลือกคอลัมน์นั้นเพื่อดูสถิติ min/max/average เลือกเครื่องจากเมนู **เพิ่มกราฟ** เพื่อเปิดกราฟหลายแหล่งพร้อมกัน

ปุ่ม **บันทึกข้อมูล** ส่งออกแหล่งกราฟที่เลือกอยู่ รวมข้อมูลในช่วง 30 วัน เป็น `monitor_YYYYMMDD_HHMMSS.txt` แบบ tab-separated ในโฟลเดอร์ส่งออก และเริ่มดาวน์โหลดไฟล์นั้น ส่วนปุ่ม **PNG** ในแต่ละการ์ดดาวน์โหลดภาพกราฟ

## ข้อควรระวัง

- ตรวจสอบว่า IIS/Apache อ่านไดรฟ์ `E:` ได้ภายใต้บัญชี service จริง บัญชี App Pool อาจไม่เห็น mapped drive; ใช้ local path หรือ UNC share พร้อมกำหนดสิทธิ์ให้เหมาะสม
- จำกัดการเข้าถึงด้วย IIS Authentication, Windows Authentication หรือเครือข่ายที่เชื่อถือได้ โดยเฉพาะหน้า Settings และ API บันทึกการตั้งค่า
- `config`, `logs` และ `exports` มีข้อกำหนดปิดการเข้าถึงไฟล์ตรงด้วย `web.config` (IIS) และ `.htaccess` (Apache); คงการป้องกันนี้ไว้เมื่อเผยแพร่
- หากต้องการไม่พึ่ง CDN ให้ดาวน์โหลด Chart.js, chartjs-plugin-zoom, Hammer.js และฟอนต์ที่ใช้มาให้บริการจากเว็บเซิร์ฟเวอร์ภายใน แล้วแก้ `<script>` ใน `index.php` และ `@import` ใน CSS
- ช่วงย้อนหลังอิงวันที่ในชื่อไฟล์แบบ `YYYYMMDD`; ไฟล์ที่ชื่อไม่ตรง pattern หรือเก่ากว่า 30 วันจะไม่ถูกรวม แม้จะยังอยู่ในโฟลเดอร์
- หากชนิดข้อมูลหรือ header ของ CSV ต่างจากตัวอย่าง ให้ตรวจสอบ encoding (แนะนำ UTF-8) และรูปแบบหัวตารางก่อนใช้งาน
